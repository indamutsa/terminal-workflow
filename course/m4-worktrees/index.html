    Worktrees and the agent loop · Page 1 of 4

    Parallel branches without stashing

    Check out several branches at once, each in its own folder.

    The one idea

    A worktree is another folder on another branch, sharing one git history.

    • Create → git worktree add ../dir -b branch. A new folder on a new branch.
    • List → git worktree list. Every folder and its branch.
    • Remove → git worktree remove ../dir. Deletes the folder.
    • Prune → git worktree prune. Clears stale entries.
    The problem

    Mid-feature, a hotfix lands. You stash, switch branches, switch back and hope the stash pops cleanly.

    The fix: Give each branch its own folder with git worktree add. No stashing, no switching.

    Worked application

    Start a feature without touching main

    The setup

    You begin a payments feature and keep ~/tw on main exactly as it is.

    1. Keys: git worktree add ../tw-payments -b feature/payments · Makes the folder and the branch.
    2. Keys: git worktree list · Two folders, two branches.
    3. Keys: cd ../tw-payments then git branch · Marks feature/payments as current. Edit freely: ~/tw stays on main.
    4. Keys: cd ../tw then git worktree remove ../tw-payments and git branch -d feature/payments · Removes the folder and the branch.
    You see

/Users/you/tw-payments 3f2a1b9 [feature/payments]
    Why it matters: A branch becomes a place you can walk into. Switching branches is a cd.

    The three-window pattern

    Main, your editor and an AI agent: three windows, one feature branch.

    The one idea

    One worktree, two windows on it: you in one, the agent in the other.

    • Main → Ctrl-a 1. PR reviews, releases, rebases.
    • Editor → Ctrl-a 2. You: nvim, tests, review.
    • Agent → Ctrl-a 3. The coding agent generates code.
    • Workspace → git worktree add ../my-service-payments -b feature/payments main. The feature folder.
    The problem

    The agent and your editor fight over the same checkout, and half-finished edits land on your main branch.

    The fix: Give the feature its own worktree. You and the agent edit the same branch from different terminals.

    Create the workspace

    Window 1 is main. Window 2 is your editor. Window 3 is your AI coding agent, on the same feature branch.

    Worktrees and the agent loop · Page 4 of 4

    Test, ship, clean up

    Run the tests, send fixes to the agent, open a PR and remove the worktree.

    The one idea

    Test, fix, commit, push, open a PR, then remove the worktree. Main never gets dirty.

    • Run tests → npm test -- --grep payments. Or pytest tests/payments/ -v.
    • Commit → git commit -m "Add payments endpoint with Stripe integration". On the feature branch.
    • Open a PR → gh pr create. Against the pushed branch.
    • Clean up → git worktree remove ../my-service-payments. After the merge.
    The problem

    A failing test sits in one window while the agent sits idle in another. After the merge, dead worktrees pile up.

    The fix: Copy the failure to the agent, ship from the feature window, then remove the worktree and branch.

    Worked application

    From failing test to merged PR

    The setup

    In ~/tw-payments from the last page, a run fails and you want it fixed, shipped and cleaned up. Your repo has an origin.

    1. Keys: python3 orders.py · In the editor window. If it fails, paste the error to the agent in Window 3, then run it again.
    2. Keys: git add -A, git status, then git commit -m "Fix the total" · Stages the fix, lists it and commits.
    3. Keys: git push -u origin feature/payments, then gh pr create --fill · Publishes the branch and opens the PR.
    4. Keys: After the merge: cd ~/tw, git pull, git worktree remove ../tw-payments, git branch -d feature/payments · Pulls the merge, then removes the folder and the branch.

https://github.com/you/tw/pull/1
$ git branch -d feature/payments

    Why it matters: The loop is test, tell the agent, retest, ship, clean up. Each step lives in the window built for it.
