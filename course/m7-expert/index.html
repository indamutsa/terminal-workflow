    Repeat an edit on every match in Neovim

    Change the 2nd quoted string, delete up to a word, change up to a comma, change every match one by one, repeat the last change

    The one idea

    Repeat an edit with one key: shape the change so `.` can run it again.

    • Change the 2nd quoted string → 2ci". Change the text inside the 2nd pair of quotes.
    • Delete up to a word → d/pattern. Delete everything up to the match.
    • Change every match one by one → cgn. Change the next match, then press `.`.
    • Repeat the last change → .. Run the last change again.
    The problem

    How do I change the same text in many places without retyping it? You count characters, hold l and retype the same change at every match.

    The fix: Land exactly with counts, searches and till-motions, then use cgn and . to repeat the change.
    Type it

    Open the Neovim practice project

    How do I try these drills safely? Every drill runs against nvim-drills. These are throwaway reps: undo with u once you have seen the mechanic work. Autosave writes a file about 3 seconds after you stop typing, and when you leave the buffer, so :e! cannot bring the original back. For a drill that must stay unsaved, run :ASToggle first and again after it. To reset one file, run git checkout -- <file>. Lesson 6 makes the permanent fixes, but none of these drills depend on it.

    Type it

    Repeat a command with a count (3dw, 5j, 2ci")

    Add a count to almost any command.

    Type it

    Delete or change up to a search match (d/pattern)

    A search only deletes text when you give it to an operator.

    Type it

    Change up to a character, not including it (t and T)

    Stop before a character with t, or land on it with f.

    Type it

    Delete or copy several lines with relative line numbers

    Turn on relative line numbers with :set relativenumber. Then you can read each count straight off the screen.

    Type it

    Change inside the next or Nth brackets, quotes or argument

    How do I change inside the 2nd enclosing braces? With mini.ai the count goes before the i or a: c2i{, not ci2{. After an operator, vim reads i{ as a two-character text object, so a digit between them is not a count.

    Type it

    Repeat a change with the dot (.) and review each match

    The . command repeats the last change. Shape every edit so it can repeat. cgn plus . beats :%s when you want to review each change.

    How do I change several matches without multiple cursors? Press * to select a word into the search register, cgn to change the current match, . to apply it to the next, n to skip one, . to change this one. You get interactive find-and-replace with undo per match.

    Why do I press n twice to skip a match when I use cgn and .?

    hint

    step-by-step solution

    2. gn operates on the match under the cursor, so . would change it.

    Change every match in a project: quickfix, marks and :g

    Replace text in every file, collect all TODOs, bookmark files, rewrite text with regex, delete lines that match a pattern

    The one idea

    Collect every match once, then change all of them.

    • Collect all search results in a list → Ctrl-q. Send the results to the quickfix list.
    • Replace text in every listed file → :cdo s/a/b/g. Replace across the list.
    • Bookmark a file and line → mA. Mark a file and line.
    • Delete every line that matches → :g/pattern/d. Delete every line that matches.
    The problem

    How do I stop changing one file at a time, and stop a regex rewrite from touching lines I want to keep?

    The fix: Collect matches in quickfix, bookmark files with marks and limit substitution with ranges and :g.
    Type it

    Collect every search result in one list (quickfix)

    Quickfix holds results for the whole project. The location list belongs to one buffer.

    How do I replace text in every file? Press <Space>/ to grep, Ctrl-q to send all results to quickfix, then :cdo s/old/new/g | w to replace across all files, or :cfdo %s/old/new/g | w for the same per file (faster).

    Type it

    Bookmark a place and jump back to it (marks)

    Vim sets the automatic marks for you. Use A to D for your four most-used files.

    Type it

    Search and replace with regex groups, case and ranges

    Use groups, case changes, expressions and ranges.

    How do I check the result? Not with <Space>sg item. That greps the whole project, and orders.py and messy.py legitimately use item as a variable name. Press u to undo it.

    Type it

    Run a command on every line that matches (:g)

    Run a command on all lines that match a pattern. :v does the opposite: it runs on lines that do not match.

    Edit many files, columns and lines, and go back in time

    Open a set of files, edit a column of text, number lines, duplicate or move a line, go back to an earlier state of a file

    Edit many files and a column of text, and go back in time.

    Go back to an earlier state of a file (undo tree)

    How do I undo further than u? Vim's undo is a tree, not a line. If you undo and make new changes, the old changes are a branch, and g- and g+ walk the whole tree. Undo history is already persistent: it survives quitting Neovim.

    How do I travel through saved states? This is the one exercise in this lesson that must write to disk, because :earlier and :later with an f count are save-based. Autosave would add saves of its own and spoil the count, so pause it first and turn it back on at the end.
