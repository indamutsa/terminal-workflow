    Motions and the dot formula

    Counts, searches as motions, till-motions, text objects and the repeatable change.

    The one idea

    Shape every edit so that one key repeats it.

    • Count a quote → 2ci". Change inside the 2nd quoted string.
    • Operate to a search → d/pattern. Delete up to the match.
    • Change a match → cgn. Change the next match, then press `.`.
    • Repeat → .. Run the last change again.
    The problem

    You count characters, hold l and retype the same change at every match.

    The fix: Use counts, searches and till-motions to land exactly, then cgn and . to repeat the change.

    Advanced text objects (with plugins)

    With mini.ai the count goes before the i or a: c2i{, not ci2{. After an operator, vim reads i{ as a two-character text object, so a digit between them is not a count.

    Type it

    The dot formula

    The . command repeats the last change. Master users structure every edit to be repeatable. cgn plus . beats :%s when you want to review each change.

    Multi-cursor without multi-cursor: * selects a word into the search register, cgn changes the current match, . applies it to the next, n skips one, . changes this one. You get interactive find-and-replace with undo per match.

    Expert macros and registers

    Self-correcting and recursive macros, the expression register, appending and the black hole.

    The one idea

    Registers hold text and macros alike. Edit them, append to them and keep them safe.

    • Record → qa. Record a macro into register a.
    • Append yank → "Ayy. Add a line to register a.
    • Black hole → "_dd. Delete without touching any register.
    • History window → q:. Edit and rerun an old command.
    The problem

    A macro works on one line and breaks on the next, or a delete overwrites the text you meant to paste.

    The fix: Start every macro from a known position, append with capital registers and delete into the black hole.
    Type it

    Self-correcting macros

    Build macros that work regardless of cursor position. Start each one at a known position: 0, ^, $ or a search.

    Type it

    Recursive macros

    A macro that calls itself stops automatically when a motion fails, such as j at the last line or f: with no colon.

    Type it

    Edit a macro and save it back

    Paste the macro, edit the text, yank it back. Then @q runs the edited macro.

    Type it

    Tag every order as reviewed, two ways

    RAW_ORDERS in src/orders.py has exactly 6 entries (A1 to A6). Append # reviewed to each.

    Append, black hole and filename registers

    Lowercase registers overwrite. Uppercase appends. Use the black hole to delete without overwriting a yank.

    Press q: to open command history as an editable buffer. Navigate with j and k, edit a command and press Enter to run it.

    Quickfix, marks, substitution and :g

    Work on every match in the project, bookmark files and rewrite text with regex.

    The one idea

    Collect locations once, then act on all of them.

    • Send to quickfix → Ctrl-q. Pick results into a list.
    • Run on every entry → :cdo s/a/b/g. Replace across the list.
    • Global bookmark → mA. Mark a file and line.
    • Act on matching lines → :g/pattern/d. Delete every line that matches.
    The problem

    You change one file at a time, and a regex rewrite touches lines you wanted to keep.

    The fix: Collect matches in quickfix, bookmark files with marks and scope substitution with ranges and :g.
    Type it

    Quickfix and location lists

    Quickfix holds project-wide results. The location list is buffer-local.

    The power workflow: <Space>/ to grep, Ctrl-q to send all results to quickfix, :cdo s/old/new/g | w to replace across all files, or :cfdo %s/old/new/g | w for the same per file (faster).

    Type it

    Marks: expert patterns

    Vim sets the auto-marks for you. Use A to D for your four most-used files.

    Groups, case modifiers, expressions and ranges.

    Windows, insert, block, ranges and undo

    The arglist, insert tricks, block editing, ex ranges and the undo tree.

    The one idea

    The last techniques: edit many files, columns and time itself.

    • Arglist → :args src/*.py. Load a set of files.
    • Column edit → Ctrl-v. Block-select a column.
    • Duplicate line → :t.. Copy the line below itself.
    • Go back in time → :earlier 5m. Return to the file 5 minutes ago.
    The problem

    You open files one by one, edit columns line by line and undo one step at a time.

    The fix: Load files with :args, edit columns with Ctrl-v and travel through time with :earlier and g-.

    Undo: expert

    Vim's undo is a tree, not a line. If you undo and make new changes, the old changes are a branch, and g- and g+ walk the whole tree. Undo history is already persistent: it survives quitting Neovim.

    This is the one exercise in this lesson that writes to disk, because :earlier and :later with an f count are save-based.
