    Operators, motions, text objects

    Combine a verb with a target and every edit becomes two or three keys.

    The one idea

    Vim's secret: an operator plus a motion is a new command.

    • Delete a word → dw. Operator d, motion w.
    • Change inside quotes → ci". Deletes the text and starts typing.
    • Delete inside parens → di(. Keeps the parens.
    • Auto-indent file → gg=G. Operator = from top to bottom.
    The problem

    You edit by selecting with the mouse, or by deleting one character at a time.

    The fix: Name the verb and the target: ci" changes what is inside the quotes, wherever the cursor sits in them.
    Type it

    Operators and motions

    Every practice file here is in Terminal-Workflow/practice/nvim-drills. Where an edit should not stay, discard it with :e!.

    Type it

    Text objects

    Operate on structures: stuff inside brackets, quotes and tags. The pattern is operator, then a or i, then the object. a is around (includes the delimiters). i is inside (just the content).

    Open src/calculator.py first. The search leaves the cursor inside raise Exception("Cannot divide by zero").

    The pattern

    01operator + a or i + object

    One sentence, three parts.

    PartMeaning
    d c yThe verb: delete, change, yank
    iInside: just the content
    aAround: includes the delimiters
    w ( " { tThe object: word, parens, quotes, braces, tag
    02Why cW and not cw

    The dot splits a number into three words.

    KeysResult on `0.08`
    cw then 0.0750.075.08
    cW then 0.0750.075
    Worked application

    Empty a call, then take it back

    The setup

    You want the arguments of a call gone, and the parens kept.

    1. Cursor: line 19, on ( (19G f() · Keys: di( · The arguments vanish and the parens stay.
    2. Cursor: on the ( (F() · Keys: % · Jumps to the matching ).
    3. Keys: u · Restores the line.
    Before
    total = calc_totl(price, qty)
    After
    total = calc_totl()
    Why it matters: The cursor only has to be inside the object; da( would remove the parens too.

    MechanismQ1

    Why does ci" work from the middle of the quoted text?

    hint

    The object is the quotes, not the cursor.

    step-by-step solution
    1. i" means the text inside the nearest double quotes.
    2. c deletes it and enters insert mode.
    Final answer: A text object covers the whole structure around the cursor.
    KeystrokesQ2

    Which keys delete the parens and what is inside them?

    hint

    Around, not inside.

    step-by-step solution
    1. Put the cursor inside the parens.
    2. Press da(.
    Final answer: da(.
    ApplicationQ3

    Change 8% to 7.5% on the TAX_RATE = 0.08 line.

    hint

    Whole WORD, not word.

    step-by-step solution
    1. Move to 0.08 with f0.
    2. Press cW, type 0.075, press Esc.
    Final answer: cW then 0.075.
    Common mistakeQ4

    cw on 0.08 left you with 0.075.08. Why?

    hint

    How does vim see the dot?

    step-by-step solution
    1. A word stops at the dot.
    2. cw changed only the leading 0.
    3. Use cW for the whole space-delimited WORD.
    Final answer: Use cW.

    Visual mode, macros, search and replace

    Select what you mean, record an edit once, replay it on many lines.

    The one idea

    Select, record, replace: three ways to change many lines at once.

    • Select lines → V. Line-wise visual mode.
    • Column edit → Ctrl-v. Block mode. Edit many lines at once.
    • Record a macro → qa. Records into register a. q stops.
    • Replace all → :%s/old/new/g. Whole file, every match.
    The problem

    Five lines need the same fix, and you type it five times. A word appears fifty times and you edit each by hand.

    The fix: Use a column insert for the same prefix, a macro for the same edit, and :%s for the same word.
    Type it

    Visual mode

    Select first, then operate.

    Open src/orders.py and put the cursor on the {"id": "A2", ... line. ^ puts it on the opening {. Block insert happens at the cursor's column, so the column matters.

    Type it

    Macros (recording commands)

    Record keystrokes once. Replay them. Perfect for repetitive edits.

    In src/calculator.py, the Person class has five __init__ fields with no self. prefix. They are dead local variables instead of attributes.

    Start with the cursor on name. Iself. goes to the line start and inserts self.. j moves to the next field. 4@a replays on the remaining four lines (age, email, phone, address).

    Type it

    Search and replace

    :%s works on the whole file. Add c to confirm each change.

    Open data/log.txt first: ten lines like item 1: pending, mixed with # TODO comments and blank lines.

    Worked application

    Fix four lines with one macro

    The setup

    Four assignments need an order_ prefix.

    1. Cursor: line 15, on name (15G) · Keys: qa I then order_ then Esc j q · Records one edit into register a and ends on the next line.
    2. Keys: 3@a · Replays it on lines 16 to 18.
    3. Keys: :e! · Discards the edit.
    Before
    name = "pen"
qty = 3
price = 2.50
note = "rush"
    After
    order_name = "pen"
order_qty = 3
order_price = 2.50
order_note = "rush"
    Why it matters: The macro ends on the next line, so it chains: record one clean edit and let the count do the rest.

    2. Each replay starts where the last one stopped.

    2. Press I, type # , press Esc.

    Your block insert landed in the wrong column. Why?

    Indent, registers, marks, many files

    Fix indentation, keep several clipboards, bookmark places and edit across files.

    The one idea

    Indent in one key, keep many clipboards, jump to bookmarks, edit many files.

    • Auto-indent file → gg=G. Fixes indentation everywhere.
    • Named register → "ayy. Yank a line into register a.
    • Global mark → mA. Jump back from any file with 'A.
    • Many files → :args src/*.py. Load files, then run :argdo.
    The problem

    A paste is mis-indented. A delete wiped what you copied. A bookmark only works inside one file.

    The fix: Re-indent with gg=G, paste the last yank with "0p, and use an uppercase mark such as mA across files.
    Type it

    Indentation and formatting

    src/messy.py has three functions and a class with deliberately inconsistent, but valid, indentation.

    Type it

    Registers (multiple clipboards)

    Vim has 26 named registers (a-z) plus special ones. Yank something, delete something else, and the default register is overwritten. "0p pastes what you originally yanked.

    ]p matches the indent of the surrounding line, a shallow fix. For full reformatting, do p then ='].

    Type it

    Marks (bookmarks)

    Lowercase marks (a-z) are per-file. Uppercase marks (A-Z) are global, across files.

    Type it

    Multi-file operations

    Workflow: <Space>/ to grep, Ctrl-q to send to quickfix, then :cdo s/old/new/g | w.

    :args src/*.py loads the four real modules plus the empty __init__.py (and scratch.py if the git drills created it). :next and :prev flip through the buffers and show the marker at the bottom of each. The full form, :argdo %s/old/new/g | w, is for when you want the change saved.

    Change every copy of a word

    Do VS Code's Cmd+D, Cmd+Shift+L and F2 in Neovim.

    The one idea

    Search for a word once, then let one key change each copy.

    • One copy at a time → * cgn .. Cmd+D the Vim way.
    • Every copy at once → :%s//new/g. Reuses the word you just searched.
    • Same column → Ctrl-v. Edit many lines together.
    • Rename a symbol → <Space>cr. Every file, real references only.
    The problem

    A name appears five times. In VS Code you press Cmd+D five times. In Neovim you retype the same change five times.

    The fix: Search the word with *, change the first copy with cgn, then press . for each next copy. Or change them all with :%s//new/g.
    Type it

    Cmd+D the Vim way: * then cgn

    * searches the word under the cursor. cgn changes the next match. . repeats it on the one after.

    Open the file with nvim ~/tw/orders.py. * jumps to the next copy of the word, so the first cgn changes line 19 and the dots go on from there.

    Why . here and not ciw? After ciw, . changes the word under the cursor again, so the cursor must walk to the next copy first. After cgn, . finds the next copy itself.

    . changes the copy you stand on, or the next one if you are not on a copy. To skip one, press n to land on it, then n again to pass it, then ..

    Type it

    Cmd+Shift+L: change them all with :s

    An empty pattern means the last search. Press *, then substitute with nothing between the slashes.

    As you type a :s command, Neovim previews the change in the file before you press Enter. Press Esc to cancel.

    Type it

    Alt+Click and Cmd+Option+Down: column and line edits

    A column edit adds the same text to a run of lines. :g with norm does it to every matching line.

    Open the file with nvim ~/tw/todo.txt. Lines 1 to 10 are item N: pending, and item 10 is longer than the rest.

    Type it

    F2 and Cmd+Shift+H: rename a symbol, replace across files

    Searching text is not the same as knowing code. The language server renames the real symbol, and grug-far replaces text across files.

    Module 5 teaches <Space>cr and <Space>sr step by step, with the same orders.py rename.

    A plugin called multicursor.nvim brings VS Code's multiple cursors to Neovim. It is not installed here, and the keys above do the same jobs.

    Rename qty in one file

    The setup

    The name qty appears five times and should read quantity.

    1. Cursor: line 16, on qty (16G) · Keys: * · Searches for qty and jumps to line 19.
    2. Keys: cgn quantity Esc · Changes the match on line 19.
    3. Keys: . four times · Changes lines 20, 6, 7 and then 16. The search wraps to the top.
    4. Keys: :e! · Discards the edit.

    After
    total = calc_totl(price, quantity)
print(name, quantity, price, note, total)
    Why it matters: The first cgn changes one copy, and each . finds the next, so one clean edit becomes five.

    Practice: change every copy

    MechanismQ1

    Why does . after cgn move on to the next copy?

    hint

    What does gn select?

    step-by-step solution
    1. gn selects the next match.
    2. . repeats cgn, so it changes the next match.
    Final answer: . repeats cgn, which finds the next match itself. After ciw, . stays on the cursor.

    You changed one copy with cgn. Skip the next copy and change the one after.

    hint

    n moves without changing.

    step-by-step solution
    1. Press n to land on the next copy.
    2. Press n again to pass it.
    3. Press ..
    Final answer: n n ..
    ApplicationQ3

    Rename the loop variable code on lines 11 and 12 without touching codes.

    hint

    Whole words only.

    step-by-step solution
    1. Press 11G, then fc to land on code.
    2. Press *, then cgn, the new name and Esc.
    3. Press . twice.
    Final answer: * matches whole words, so codes stays. Three copies change.
    Common mistakeQ4

    You rename with cw and ., and the next edit lands in the wrong place. Why?

    hint

    Where does . act?

    step-by-step solution
    1. . repeats at the cursor.
    2. Only cgn finds the next match for you.
    Final answer: Use cgn, not cw, so each . jumps to the next copy.
