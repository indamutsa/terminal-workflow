    Keep your work running after you close the terminal

    Start a tmux session, leave it running (detach), get it back, list your sessions, rename a session, kill a session

    The one idea

    Keep your work running after you close the terminal window: run it inside tmux.

    • Start a named tmux session → tmux new -s main. Opens a session named main.
    • Send a command to tmux (prefix key) → Ctrl-a. Press it first. The next key is a tmux command.
    • Leave tmux but keep everything running (detach) → Ctrl-a d. The session keeps running.
    • Get your session back (reattach) → tmux attach. Brings back everything where you left it.
    The problem

    Why did my running processes die when I closed the terminal or the laptop went to sleep?

    The fix: Run everything inside a tmux session. Detach with Ctrl-a d, and tmux attach brings it all back.

    Split your terminal into windows and panes

    Open a new window, switch windows, split the screen side by side or top and bottom, zoom one pane, resize panes

    The one idea

    Run several jobs in one terminal: a session holds windows, and a window holds panes.

    • Open a window for each job → Ctrl-a c. One window per job: editor, tests, agent.
    • Switch to another window → Ctrl-a w. A picker with a live preview.
    • Split the screen side by side → Ctrl-a |. Two panes side by side.
    • Make one pane fill the screen (zoom) → Ctrl-a z. One pane fills the screen. Press again to unzoom.

    How do I run an editor, tests and an AI agent in one terminal? They fight for the same screen.

    Change tmux colors and keys, add plugins and restore after a reboot

    The one idea

    Change how tmux looks and behaves: edit one file, `~/.config/tmux/tmux.conf`.

    • Reload the tmux config → Ctrl-a r. Applies your config changes.

    • Get your saved workspace back (restore) → Ctrl-a Ctrl-r. Brings the saved workspace back.

    Why are my tmux windows gone after I restart my computer? The restart kills the tmux server.

    The fix: Save with resurrect and continuum, then restore once at login with a lock-guarded script.

    How do I restore tmux after a reboot?

    01What happens at login after a reboot

    One path, zero pileup.

    StepWhat happens
    1. Log inlaunchd runs boot-restore.sh: starts the server and restores main once, lock-guarded
    2. Attachto main (tmux new-session -A -s main) attaches to the restored session
    3. No re-runsContinuum restore is on and fires once per server start; the lock blocks repeats
    02Why does the restore fail after a reboot?

    Four things that bit.

    GotchaFix
    launchd's PATH excludes /opt/homebrew/bin, so resurrect's bare tmux calls fail silentlyExport PATH in the boot script
    tmux start-server alone can exit with no session attachedAnchor it with new-session -d -s main
    Plist Label contains .plist or is not reverse-DNSUse com.you.name
    Several restores at once: continuum, the boot agent and iTerm2That is the pileup. Send every restore through the lock-guarded script
    03Why not use continuum-boot?

    It starts on boot, but opens Terminal.app on every login and still races with iTerm2.
