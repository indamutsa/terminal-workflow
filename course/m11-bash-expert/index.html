    Functions, strings and arrays

    Reuse a command, reshape a filename and keep a list of values whole.

    The one idea

    Use functions for repeated work, expansions for text and arrays for lists.

    • Call a function → greet Ada. $1 belongs to this call.
    • Capture a function's output → value=$(fn). return sets a status; echo prints text.
    • Strip a file suffix → ${f%.txt}. The shortest matching suffix is removed.
    • Pass every array element → "${a[@]}". Each value stays one argument.
    The problem

    A helper changes a caller's variable, or a list loses filenames that contain spaces.

    The fix: Keep helper variables local. Store lists in arrays and expand them with "${a[@]}".
    Type it

    Reuse a function

    Type bash first. Run this page's blocks in order in that shell. Type exit to return to zsh.

    return takes a status from 0 to 255, not a string. echo or printf sends data to stdout. $(fn) captures stdout and strips trailing newlines. It runs in a subshell, so variable changes there do not reach the caller. A function without return uses its last command's status.

    Type it

    Reshape strings and paths

    These expansions change the value you print. They do not rename a file.

    # removes a matching prefix and % a matching suffix. Double them to remove the longest match. The pattern is a shell glob. ${p%/*} stays unchanged if p has no slash; use dirname when you need that case handled.

    macOS /bin/bash is 3.2 here. ${s^^} for uppercase and ${s,,} for lowercase are Bash 4+ only. Many GNU/Linux systems have a newer Bash; tr works on both. These LC_ALL=C examples convert ASCII letters.

    Type it

    Keep a list in an array

    An indexed array starts at 0. Use [@] inside quotes to keep each value whole.

    A line list keeps spaces and backslashes but cannot encode a newline inside a filename. find -print0 and read -d '' use NUL separators, so the array preserves those names too. Sorting printed names here only makes these sample results stable. mapfile is Bash 4+ only. Page 3 explains < <(command).

    Safe scripts

    Catch failed commands, retain temporary work and trace the line that failed.

    The one idea

    Enable failure checks inside scripts, then handle expected failures explicitly.

    • Catch three kinds of bug → set -euo pipefail. Failed commands, unset values and broken pipelines.
    • Clean up on exit → trap cleanup EXIT. Preserve the script's original status.
    • Report a failing line → trap ... ERR. Use set -E to inherit ERR in functions.
    • Trace a script → bash -x trace.sh. Shows expanded commands on stderr.
    The problem

    A failed step goes unnoticed, temporary work is left in the active folder and the script reports success.

    The fix: Catch unexpected failure, keep an EXIT cleanup and use explicit checks for expected failure.
    Type it

    Catch bugs early

    Type bash first. Run this page's blocks in order in that shell. Type exit to return to zsh. The options below run in child shells so your interactive shell stays open.

    -e stops on eligible failures; -u rejects unset values; pipefail makes a pipeline return the rightmost nonzero status. -e and ERR skip failures tested by if, while, ! and most && / || lists. A function called as a condition also runs without errexit protection. Check important steps explicitly there. -u still allows empty values, so validate required input too.

    Type it

    Retain work and report errors

    Put cleanup in EXIT so it runs after success or failure. This exercise moves work to retained/ instead of deleting it.

    mktemp -d creates a unique private directory. An EXIT trap runs on normal shell exit, including exit after -e; it cannot run after SIGKILL or a power loss. Capture $? before cleanup commands overwrite it. The retained files remain available for inspection.

    For grep, 0 means found, 1 means no match and 2 means an error. A fallback after || runs for any failure: distinguish statuses if they need different handling. Save $? before printing anything.

    Type it

    See what ran

    Trace a whole script or just the part you are investigating.

    Tracing prints expanded arguments, so enable it only around values that are safe to display. set +x stops the trace.

    Install ShellCheck on macOS with brew install shellcheck; on Debian/Ubuntu use sudo apt install shellcheck. Then run shellcheck trace.sh. Installation and lint results are not assumed here. Bash 3.2 supports all options and traps on this page.

    Redirection, here-docs and process substitution

    Send output where you need it and feed commands text or another command's result.

    The one idea

    Redirections run left to right. Choose a stream, then choose its destination.

    • Save stdout and stderr → cmd > run.log 2>&1. Both streams reach the same file.
    • See output and save it → cmd | tee run.log. Tee copies stdin to the screen and a file.
    • Keep here-doc text literal → <<'EOF'. No dollar or command expansion.
    • Compare command output → diff <(cmd1) <(cmd2). Two readable paths replace temporary files.
    The problem

    Errors still print on the screen, or a piped loop loses its updated counter.

    The fix: Redirect stdout before copying stderr. Feed a loop with < <(cmd) to keep its state.
    Type it

    Choose the stream

    Type bash first. Run this page's blocks in order in that shell. Type exit to return to zsh.

    With 2>&1 > file, stderr copies the current stdout destination, then only stdout moves to the file. With > file 2>&1, both reach the file. > replaces existing contents; >> appends. &> is Bash syntax. The portable shell form is > file 2>&1.

    Type it

    Supply text directly

    A here-doc ends at its delimiter on a line by itself. Quotes on the delimiter control expansion.

    The two indented lines above start with actual tabs. <<- strips leading tabs from the body and delimiter, but does not strip spaces. The copy button preserves those tabs.

    A here-string adds a newline. Here-strings and process substitution work in Bash 3.2 on macOS and in Bash on GNU/Linux; they are not POSIX sh syntax.

    Type it

    Feed commands and whole scripts

    <(cmd) supplies a readable path. The separate < before it redirects that path into a loop.

    Diff returns 0 for equal inputs, 1 for differences and a larger status for trouble. Process substitution's producer status is not returned by diff and is not covered by pipefail; use checked intermediate files when producer failure must stop the job.

    Use exec > logfile 2>&1 inside a script: it changes that shell's streams for all later commands. Running logall.sh as a child keeps your interactive prompt attached to the terminal.

    Ready-made scripts

    Create and run a small backup, rename, batch, parser, retry or confirmation script.

    The one idea

    Use one small script per job. Preview changes and check failures before continuing.

    • Back up a folder → bash backup.sh source. A dated tar archive preserves the files.
    • Preview a bulk rename → bash rename.sh. Apply only after reading the dry run.
    • Retry a failed command → bash retry.sh 3 1 cmd. Limit attempts and pause between them.
    • Confirm before continuing → bash confirm.sh. Only yes or y proceeds.
    The problem

    An ad hoc command overwrites a file, retries forever or continues after a declined prompt.

    The fix: Keep a dry-run default, reject collisions, cap retries and treat EOF as a declined confirmation.
    Type it

    Back up and preview changes

    Type bash first. Run this page's blocks in order in that shell. Type exit to return to zsh. Each example creates its script with a quoted here-doc and runs it with bash.

    The archive name contains today's date and a unique suffix, so a second run cannot overwrite an older backup. tar -tzf lists its contents without extracting. The printed name varies per run. BSD tar can preserve macOS metadata; GNU tar on Linux may show different metadata entries for real folders.

    Read the first two preview lines before running bash rename.sh --apply. The example then prints the applied renames and final names. A collision stops the script; earlier renames are not rolled back. mv -n also avoids overwriting if a destination appears after the check.

    Type it

    Batch work and flags

    The input parsing is the pattern from Bash basics, now packaged as a reusable script.

    This batch helper passes each file on stdin, so use a command that reads stdin. It visits immediate children only. Use the NUL-separated find pattern on page 1 for recursive work.

    Type it

    Retry and ask before proceeding

    Retries use an attempt limit and a pause. The confirmation is tested with supplied input so this page runs without waiting.

    N counts total attempts, including the first. Only failed attempts with another attempt left sleep. The final failure returns the command's status. Use retries for commands that are safe to repeat. A command or function tested in if must handle its own internal failures.

    Run bash confirm.sh to answer at the terminal. The prompt uses printf, so it also appears when input is piped. Empty input, EOF and answers outside the listed yes forms cancel.
