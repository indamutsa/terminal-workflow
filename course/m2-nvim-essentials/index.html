    Open, move, save, quit

    Open the practice project, find a file, make an edit, save it and get out.

    The one idea

    Four moves cover a first edit: open, find, type, save.

    • Open → v .. Opens Neovim with the file explorer.
    • Find a file → <Space>sf. Fuzzy search by name. Your Cmd+P.
    • Search text → <Space>sg. Grep inside every file.
    • Save and quit → :wq. Writes the file and leaves.
    The problem

    You open Neovim and typing does nothing useful. You cannot find a file, and you cannot get out.

    The fix: Press i to type and Esc to stop. Save with :w, leave with :q. The exit table below gets you out of anything.
    Type it

    Setup: the practice repo

    Every exercise runs against a small Python project with deliberate flaws. This lesson only moves around in it.

    The project has bad names, an unused import, an off-by-one bug and a failing test. You fix none of that here. Undo a throwaway edit with u.

    Autosave writes a file about 3 seconds after you stop typing, and when you leave the buffer. So :e! cannot bring back the original once that has happened. To make :e! work, run :ASToggle before a throwaway drill and again after it. With autosave paused, a changed file stays unsaved until you run :w.

    A file ends up changed anyway? For ~/tw, run the Get the practice files box at the top of this page again. For nvim-drills, run git checkout -- <file> in that folder.

    Type it

    Open a project

    Run this from inside nvim-drills. v with no argument opens the dashboard. v . opens the file explorer.

    v. is the same as v ., and vi and vim run v too.

    Type it

    Navigate files without a mouse

    Learn <Space>sf and <Space>sg. You will use them a hundred times a day.

    The <Space>s search group: sf files, sg grep, sw word, sk keymaps, sh help, sd diagnostics, sr search and replace. Press <Space>s and wait to see them all.

    Type it

    Edit, save, quit

    The rhythm: i to type, Esc to stop, :w to save.

    02Quick start

    The first five minutes of Neovim.

    Worked application

    Save, undo, save

    The setup

    You make a throwaway edit and leave the file clean.

    1. Cursor: line 1 (gg) · Keys: O then # scratch then Esc · Opens a line above and types the comment.
    2. Keys: :w · Saves.
    3. Keys: u then :w · Undoes the edit and saves the original again.
    Before
    TAX_RATE = 0.08
    After
    # scratch
TAX_RATE = 0.08
    Why it matters: Save, undo, save is the safe loop for any throwaway edit.

    MechanismQ1

    Why does typing do nothing when Neovim opens?

    hint

    Which mode do you start in?

    step-by-step solution
    1. Neovim starts in normal mode, where keys are commands.
    2. Press i to enter insert mode.
    Final answer: Normal mode treats keys as commands. i switches to typing.

    Which keys save and leave in one go, without a colon?

    hint

    Two capital letters.

    step-by-step solution
    1. Make sure you are in normal mode.
    2. Press ZZ.
    Final answer: ZZ. The same as :wq.
    ApplicationQ3

    Find every use of TAX_RATE in the project.

    hint

    Search inside files, not file names.

    step-by-step solution
    1. Press <Space>sg.
    2. Type TAX_RATE and press Enter.
    3. Move through the matches with Ctrl-n and Ctrl-p.
    Final answer: <Space>sg, then TAX_RATE. Five matches in two files.
    Common mistakeQ4

    You are in a terminal inside Neovim and nothing navigates. What first?

    hint

    Terminal mode has its own exit.

    step-by-step solution
    1. Press Ctrl-\ Ctrl-n to leave terminal mode.
    2. Now navigation keys work again.
    Final answer: Ctrl-\ Ctrl-n.

    Move fast and search

    Jump by word, line, bracket or pattern. Hold no arrow keys.

    The one idea

    Every jump has a short key. Learn the jumps and the file stops being long.

    • Word → w / b / e. Forward, back, end of word.
    • Line → 0 / $ / ^. Start, end, first non-blank.
    • File → gg / G. Top or bottom. 42G goes to line 42.
    • Search → /pattern. Then n and N step through the matches.
    The problem

    You hold j to reach line 50, overshoot, and scroll back. Finding one word means reading the whole screen.

    The fix: Jump with 51G, % and gg. Search with /pattern and step with n.
    Type it

    Move fast

    Line numbers can drift if you edited the file earlier. /RAW_ORDERS then Enter always works too.

    Type it

    Searching

    src/orders.py has a TODO above calc and a FIXME above qualifies_for_free_shipping.

    Put the cursor on calc after the TODO comment and press * to jump to its next use. Use # to search backward and compare.

    Type it

    Entering insert mode

    Instead of $a, press A. Each variant saves a step.

    Delete, yank, paste, undo

    Cut, copy, paste and comment lines, then undo and repeat any change.

    The one idea

    Delete and yank are one or two keys. Undo and repeat make mistakes cheap.

    • Delete a line → dd. Cuts the whole line.
    • Copy a line → yy. Yank. Paste with p.
    • Comment → gcc. Toggle a comment on the line.
    • Undo → u. Ctrl-r redoes. . repeats.
    The problem

    You delete the wrong line and have no idea how to get it back. You retype the same edit on ten lines.

    The fix: Undo with u, redo with Ctrl-r, and repeat the last change with ..
    Type it

    Delete, yank, paste

    Type it

    Undo, redo, repeat

    The . command repeats your last change. Make a change, move to another word, press ..

    02Undo a throwaway edit

    Three ways back, from smallest to biggest.

    SituationKeys
    Undo the last changeu
    Redo itCtrl-r
    Reload from disk (autosave paused with :ASToggle first):e!
    Worked application

    Mark two lines done, then undo

    The setup

    You change one word on two lines, then take both changes back.

    1. Cursor: line 1, on pending (1G fp) · Keys: ciw then done then Esc · Replaces the word.
    2. Cursor: line 2, on pending (j 0 fp) · Keys: . · Repeats the same edit.
    3. Keys: u u · Both lines say pending again.
    4. Keys: Ctrl-r Ctrl-r · Both say done again.
    5. Keys: u u · Both lines say pending again. Autosave writes the original back.
    Before
    item 1: pending
item 2: pending
    After
    item 1: done
item 2: done
    Why it matters: One edit, repeated with a key, and fully reversible.

    Change pending to done on two lines without retyping.

    hint

    Change once, then repeat.

    step-by-step solution
    1. On the first line, run ciw, type done, press Esc.
    2. Move to the second line and press ..

    Common mistakeQ4

    You edited a lesson file and want it clean. What do you run?

    hint

    Undo, step by step.

    step-by-step solution
    1. u undoes one change at a time, so press it until the text is back.
    2. :e! discards edits that are not saved yet, and autosave has usually saved the edit already (pause it with :ASToggle first).
    Final answer: u until it is clean.

    Buffers, terminals, splits, tabs, leader

    Work on several files and a terminal at once, and discover keys as you go.

    The one idea

    Buffers are open files. Splits and tabs arrange them. The leader key finds the rest.

    • Next buffer → Shift-L. Shift-H goes back.
    • Terminal → Ctrl-\. Opens the last terminal you used. Press again to hide.
    • Split → :vsplit file.py. Two files side by side.
    • Discover → <Space>. Wait for the which-key menu.
    The problem

    You keep closing one file to open another. Running the tests means leaving the editor.

    The fix: Cycle open files with Shift-H and Shift-L, open a terminal with Ctrl-`, and split the screen when you need two files.
    Type it

    Buffers (open files)

    Cycle through the three source files.

    Type it

    Terminals inside Neovim

    Terminals are Snacks terminals and open in :pwd. Ctrl-` and Ctrl-/ toggle the last terminal you used, whether float, right or bottom.

    These are lowercase <Space>t keys, next to the test keys. Each of the three keeps its own terminal. For several long-running terminals, prefer tmux panes (Ctrl-a |, Ctrl-a -). The built-in splits below also work.

    Open the terminal first (Ctrl-`). If pytest is not the one on your PATH, run python3 -m pytest. Then Ctrl-\ Ctrl-n to leave terminal mode and press the toggle again to close it. The pass count can drift if you left a file edited: press u until it is back to the original, give autosave 3 seconds, and re-run.

    Type it

    Copy and paste inside Neovim

    Cmd+C and Cmd+V do not work inside Neovim. Your clipboard is synced (unnamedplus), so anything you y is ready for Cmd+V outside.

    Type it

    Splits (multiple files visible)

    From the picker, press Ctrl-v (vsplit) or Ctrl-s (hsplit) instead of Enter to open a file in a split.

    A "Pick window" prompt means the cursor is in the explorer sidebar. Press Esc, then Ctrl-l to reach the code area, or close the explorer with ` before splitting.

    Type it

    Tabs (separate workspaces)

    A tab is a layout. Each tab has its own arrangement of splits. For switching files, use buffers.

    Type it

    The leader key

    <Space> is your leader key. Press it and wait: the which-key popup shows every command group.

    Forgot a key? Press <Space> and read the menu, or <Space>sk to fuzzy-search every keymap by description.
