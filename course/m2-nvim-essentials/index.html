    Open, edit, save and quit Neovim

    Open a project in Neovim, find a file by name, search text in every file, save and quit, get out when you are stuck

    The one idea

    Open a project, find a file, type and save: four moves cover a first edit.

    • Open a project in Neovim → v .. Open Neovim with the file explorer.
    • Find a file by name → <Space>sf. Fuzzy search by name. Your Cmd+P.
    • Search text in every file → <Space>sg. Search (grep) inside every file.
    • Save and quit → :wq. Write the file and leave.
    The problem

    Why does typing do nothing when I open Neovim? I cannot find a file, and I cannot get out.

    The fix: Press i to type and Esc to stop. Save with :w, leave with :q. The exit table below gets you out of anything.
    Type it

    Set up the practice project

    Every exercise runs against a small Python project with deliberate flaws. This lesson only moves around in it.

    Undo a throwaway edit with u. The project has bad names, an unused import, an off-by-one bug and a failing test. You fix none of that here.

    Why can :e! not bring back the original file? Autosave writes a file about 3 seconds after you stop typing, and when you leave the buffer. Once that has happened, :e! cannot bring back the original. To make :e! work, run :ASToggle before a throwaway drill and again after it. With autosave paused, a changed file stays unsaved until you run :w.

    Get a changed practice file back: for ~/tw, run the Get the practice files box at the top of this page again. For nvim-drills, run git checkout -- <file> in that folder.

    Type it

    Open a project folder in Neovim

    Run this from inside nvim-drills. v with no argument opens the dashboard. v . opens the file explorer.

    Other ways to open Neovim: v. is the same as v ., and vi and vim run v too.

    Type it

    Find a file and jump around the project without the mouse

    Learn <Space>sf and <Space>sg first. You will use them a hundred times a day.

    See every search key: the <Space>s search group has sf files, sg grep, sw word, sk keymaps, sh help, sd diagnostics, sr search and replace. Press <Space>s and wait to see them all.

    Type text, save the file and quit

    Move around a file fast and search in it

    Jump to a word, a line or a line number, jump to the matching bracket, search for text in a file, step through the matches

    The one idea

    Jump around a file with short keys instead of holding the arrow keys.

    • Jump by word → w / b / e. Go forward, go back, go to the end of the word.
    • Jump to the start or end of a line → 0 / $ / ^. Start, end, first non-blank.
    • Jump to the top, bottom or a line number → gg / G. Top or bottom. 42G goes to line 42.
    • Search for text in the file → /pattern. Then n and N step through the matches.
    The problem

    How do I get to line 50 without holding j? You hold it, overshoot, and scroll back. Finding one word means reading the whole screen.

    The fix: Jump with 51G, % and gg. Search with /pattern and step with n.

    Delete, copy, paste, comment and undo in Neovim

    Delete a line, copy and paste a line, comment out lines, undo a mistake, repeat the last change

    The one idea

    Delete and copy a line in one or two keys. Undo and repeat make mistakes cheap.

    • Delete a line → dd. Cut the whole line.
    • Copy a line → yy. Yank (copy) it. Paste with p.
    • Comment out a line → gcc. Toggle a comment on the line.
    • Undo, redo or repeat a change → u. Ctrl-r redoes. . repeats.
    The problem

    How do I get a deleted line back? You delete the wrong line and have no idea how to undo it. You retype the same edit on ten lines.

    The fix: Undo with u, redo with Ctrl-r, and repeat the last change with ..
    Type it

    Delete, copy (yank) and paste lines

    RAW_ORDERS in src/orders.py has six entries, A1 to A6.

    Type it

    Undo a change, redo it or repeat it

    The . command repeats your last change. Make a change, move to another word, press ..

    Work on several files, terminals and splits in Neovim

    Switch between open files, open a terminal inside Neovim, show two files side by side, use tabs, find a key you forgot

    The one idea

    Switch between open files (buffers), arrange them in splits and tabs, and press the leader key to find the rest.

    • Switch to the next open file → Shift-L. Shift-H goes back.
    • Open a terminal inside Neovim → Ctrl-\. Open the last terminal you used. Press again to hide it.
    • Show two files side by side → :vsplit file.py. Open the second file in a vertical split.
    • Find a key you forgot → <Space>. Wait for the which-key menu.
    The problem

    How do I switch files without closing one to open another? Running the tests also means leaving the editor.

    The fix: Cycle open files with Shift-H and Shift-L, open a terminal with Ctrl-`, and split the screen when you need two files.
