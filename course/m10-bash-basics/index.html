    Run a bash script, save values and check if a command worked

    Run a script file, save a value in a variable, quote a file name with spaces, check if a command worked

    The one idea

    Make a script safe with spaces and check if a command worked: quote every variable and read $? after the command.

    • Run a script file → bash hello.sh. Or chmod +x it and run ./hello.sh.
    • Save a value in a variable → name=Ada. No spaces around the equals sign.
    • Use a value with spaces safely → "$name". Double quotes keep spaces inside the value.
    • Check if a command worked → echo $?. 0 is success, anything else is a failure.
    The problem

    Why does my script work on report.txt but break on my notes.txt? Why does name = Ada say command not found?

    The fix: Fix both: write name=Ada with no spaces, and put "$name" in double quotes every time you use it.

    Run a script file: type bash and the file name, or make the file executable and run it by path.

    Which program runs my script? The first line #!/bin/bash (the shebang) names it when you run ./hello.sh. bash hello.sh ignores it.

    Save a command's output and do maths

    Save what a command prints with $(command). Do whole-number maths with $(( )).

    Why does 7 / 3 give 2? $(( )) drops the decimals: 7 / 3 is 2. For decimals pipe the sum to bc.

    Check if the last command worked: every command leaves a number, 0 for success and anything else for failure. $? holds the last one.

    Is the exit code the same on Linux? No: GNU ls exits with 2 for a missing file where macOS ls exits with 1. Only 0 versus not 0 is portable.

    Check a file, a number or text, then choose what to run

    Check if a file exists, compare two numbers, compare two strings, match a file name pattern, pick a branch with case

    The one idea

    Run a command only if something is true: put the test inside [[ ]] with spaces around everything, and let the exit code pick the branch.

    • Check if a file exists → [[ -f report.txt ]]. Also -d, -e, -s and -x.
    • Compare two numbers → [[ $n -gt 5 ]]. Or (( n > 5 )) for maths.
    • Match a file name pattern → [[ $f == *.txt ]]. No quotes around the pattern.
    • Pick a branch by value → case $x in a) ... ;; esac. Use | to join choices.
    The problem

    Why does [ $name = Ada ] error when the name is empty or has a space? Why is [[ $n=5 ]] always true?

    The fix: Use [[ ]] with a space on every side of the operator: [[ $n = 5 ]].

    Loop over files, numbers and lines in bash

    Run a command on every file, count from 1 to 5, repeat until something changes, read a file line by line, split a CSV line

    The one idea

    Repeat a command in bash: for walks a list, while repeats until a test fails, and while read walks lines.

    • Loop over files → for f in *.txt; do ...; done. Quote "$f" inside.
    • Count to five → for i in {1..5}; do ...; done. Or for ((i=0; i<5; i++)).
    • Read a file line by line → while read -r line; do ...; done < file. Safe with spaces in a line.
    • Split a CSV line into columns → while IFS=, read -r a b. IFS is the separator.
    The problem

    Why does for x in $(cat file) cut every line at its spaces? Why does a loop after a pipe lose the variable it set?

    The fix: Read lines with while IFS= read -r line; do ...; done < file, and quote "$f" in every loop.

    Type bash first: these snippets are bash, and zsh splits words differently. Type exit to return to zsh.

    Why does {1..$n} not count to my variable? Braces do not expand a variable. Use seq. GNU seq works the same on Linux.

    Repeat until something changes (while and until)

    Repeat as long as a test passes with while. Repeat as long as it fails with until.

    Make a script read arguments, flags and typed answers

    Read the first argument, give an argument a default, read -v and -n NAME flags, ask the user a question, print usage on bad input

    The one idea

    Make a script read input: arguments come from $1, $2 and $@, and flags from a case loop or getopts.

    • Read the first argument → $1. $2 is the second, $# is the count.
    • Give an argument a default value → ${1:-world}. Used when $1 is empty.
    • Read flags like -v and -n NAME → getopts "vn:" opt. A colon means the flag takes a value.
    • Ask the user a question → read -p "Name: " name. -s hides it, -t 5 times out.
    The problem

    Why does my script break on bash backup.sh "my folder"? Why does it run with a missing argument and do the wrong thing?

    The fix: Quote "$@" and "$1", require what you need with ${1:?usage}, and print usage and exit 1 on bad input.
