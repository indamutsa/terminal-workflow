    Variables, quoting and exit codes

    Run a script, keep values in variables, quote them, and read whether a command worked.

    The one idea

    Quote every variable, and read $? after a command to know if it worked.

    • Run a script → bash hello.sh. Or chmod +x it and run ./hello.sh.
    • Keep a value → name=Ada. No spaces around the equals sign.
    • Use it safely → "$name". Double quotes keep spaces inside the value.
    • Did it work → echo $?. 0 is success, anything else is a failure.
    The problem

    A script works on report.txt and breaks on my notes.txt, or name = Ada says command not found.

    The fix: Write name=Ada with no spaces, and put "$name" in double quotes every time you use it.
    Type it

    Run a script

    A script is a text file of commands. Run it with bash, or make it executable and run it by path.

    The first line #!/bin/bash is the shebang. It tells the system which program runs the file when you run ./hello.sh. bash hello.sh ignores it.

    Capture output and do arithmetic

    $(command) swaps in what the command prints. $(( )) does whole-number maths.

    $(( )) drops the decimals: 7 / 3 is 2. For decimals pipe the sum to bc.

    Type it

    Exit codes

    Every command leaves a number: 0 for success, anything else for failure. $? holds the last one.

    Linux differs: GNU ls exits with 2 for a missing file where macOS ls exits with 1. Only 0 versus not 0 is portable.

    Rules and review depth

    Variables and exit codes at a glance

    01Keep a value whole or let it split

    Bash splits an unquoted value at spaces, tabs and newlines (IFS), then expands * patterns. Quotes stop both.

    TaskWrite
    Keep a value whole"$name": one word, spaces kept. Use this by default.
    Print the text $name as typed'$name': nothing expands.
    See what unquoted does$name: split and pattern-expanded, so my notes.txt breaks.
    Put text right after a value"${name}s"
    02Save output or do maths

    Three dollar forms that look alike.

    TaskWrite
    Use a variable$name
    Save what a command printsfirst=$(head -1 file)
    Add or multiply whole numbers$((a + b))
    03Check if a command worked

    A command's success is a number.

    TaskWrite
    Read the last command's resultecho $?: 0 is success. Read it before running anything else.
    End a script with your own codeexit 3
    Make a command that always succeeds or failstrue (code 0) or false (code 1)
    Worked application

    Print the line count of a file with a space in its name

    The setup

    You want one sentence that says how many lines my notes.txt has.

    1. Keys: file='my notes.txt' · The quotes keep the space inside the value.
    2. Keys: n=$(wc -l < "$file" | tr -d ' ') · wc -l counts the lines. tr -d ' ' removes the padding spaces macOS adds.
    3. Keys: echo "$file has $n lines" · Double quotes keep the filename whole.
    You see
    my notes.txt has 2 lines
    Why it matters: Quote the variable and the filename stays one word, whatever is in it.

    Practice: variables and exit codes

    MechanismQ1

    Why does cat $f fail when f='my notes.txt', while cat "$f" works?

    hint

    How many words does the command get?

    step-by-step solution
    1. Without quotes bash cuts the value at the space.
    2. cat then gets two names, my and notes.txt.
    3. Quotes keep it as one name.
    Final answer: Unquoted $f splits into two words. "$f" stays one.
    KeystrokesQ2

    Which line stores today's year in y and prints Year: ...?

    hint

    Command substitution, then echo.

    step-by-step solution
    1. Write y=$(date +%Y).
    2. Write echo "Year: $y".
    Final answer: y=$(date +%Y) then echo "Year: $y".
    ApplicationQ3

    Make a script fail.sh that prints oops and ends with code 4. How do you check the code?

    hint

    Put exit last, then read the code.

    step-by-step solution
    1. Create it with printf 'echo oops\nexit 4\n' > fail.sh.
    2. Run bash fail.sh.
    3. Run echo $? straight after.
    Final answer: bash fail.sh prints oops, then echo $? prints 4.
    Common mistakeQ4

    count = 5 prints count: command not found. What is wrong?

    hint

    Look at the spaces around the equals sign.

    step-by-step solution
    1. Bash reads count as a command and = and 5 as its arguments.
    2. An assignment has no spaces around =.
    Final answer: Write count=5.

    Decisions

    Branch with if, test strings, numbers and files, and match patterns with case.

    The one idea

    Put the test inside [[ ]] with spaces around everything, and let the exit code pick the branch.

    • Test a file → [[ -f report.txt ]]. Also -d, -e, -s and -x.
    • Compare numbers → [[ $n -gt 5 ]]. Or (( n > 5 )) for maths.
    • Match a pattern → [[ $f == *.txt ]]. No quotes around the pattern.
    • Pick by value → case $x in a) ... ;; esac. Use | to join choices.
    The problem

    Your script tests [ $name = Ada ] and errors when the name is empty or has a space, or [[ $n=5 ]] is always true.

    The fix: Use [[ ]] with a space on every side of the operator: [[ $n = 5 ]].
    Type it

    if, elif, else

    Type bash first: these snippets are bash, and zsh splits words differently. Type exit to return to zsh.

    Type it

    Test files and combine tests

    Each file test is one letter. Join tests with && and || inside the brackets.

    Type it

    case and short-circuit

    case picks a branch by pattern. && and || run the next command on success or failure.

    Rules and review depth

    Tests at a glance

    01Check a file or folder

    One letter after the dash.

    TaskWrite
    Check a file exists[[ -f x ]] (a regular file)
    Check a folder exists[[ -d x ]]
    Check something exists (a broken symlink counts as missing)[[ -e x ]]
    Check a file is not empty[[ -s x ]]
    Check a file can be run (or a folder entered)[[ -x x ]]
    02Compare text and numbers

    Quote the right side of = to match it as literal text. Unquoted, it is a pattern.

    TaskWrite
    Check two strings match[[ $a = "$b" ]] (!= for different)
    Check a string is empty or not[[ -z $a ]] or [[ -n $a ]]
    Compare whole numbers[[ $a -lt $b ]]. Also -le -gt -ge -eq -ne.
    Compare with maths symbols(( a > b ))
    03Run a command on pass or fail

    a && b || c is not if/else.

    TaskWrite
    Run b only when a worksa && b
    Run c only when a failsa || c
    Choose between two branches safelyif a; then b; else c; fi
    Avoid this shapea && b || c also runs c when b fails.
    Worked application

    Check that a file exists and has content

    The setup

    A script should only read report.txt when it is there and not empty.

    1. Keys: f=report.txt · Name the file once.
    2. Keys: if [[ -f $f && -s $f ]]; then echo "$f has data"; else echo "$f is missing or empty"; fi · -f and -s must both pass.
    3. Keys: f=empty.txt, then run the if line again · The file exists but -s fails.
    You see
    report.txt has data
empty.txt is missing or empty
    Why it matters: One [[ ]] with && checks both facts before the script touches the file.
    Your turn

    Practice: decisions

    MechanismQ1

    Why does [[ 9 < 10 ]] come out false?

    hint

    Is < a number test or a text test?

    step-by-step solution
    1. Inside [[ ]], < compares text in dictionary order.
    2. As text, 9 sorts after 10.
    Final answer: Use -lt for numbers: [[ 9 -lt 10 ]].
    KeystrokesQ2

    Which test is true when $f ends in .log?

    hint

    A pattern on the right, no quotes.

    step-by-step solution
    1. Use == inside [[ ]].
    2. Put *.log on the right, unquoted.
    Final answer: [[ $f == *.log ]].
    ApplicationQ3

    Write a case that prints weekend for sat or sun and weekday for anything else.

    hint

    Join two choices with a pipe.

    step-by-step solution
    1. Start with case $d in.
    2. Add sat|sun) echo weekend ;;.
    3. Add *) echo weekday ;; and esac.
    Final answer: case $d in sat|sun) echo weekend ;; *) echo weekday ;; esac.
    Common mistakeQ4

    [[ -f report.txt ]] && false || echo fail prints fail though the file exists. Why?

    hint

    What runs after the middle command fails?

    step-by-step solution
    1. && runs false, which fails.
    2. || then runs on that failure.
    Final answer: a && b || c also runs c when b fails. Use if and else.

    Loops

    Repeat a command over a list, files, a range, a counter or the lines of a file.

    The one idea

    for walks a list, while repeats until a test fails, and while read walks lines.

    • Loop over files → for f in *.txt; do ...; done. Quote "$f" inside.
    • Count to five → for i in {1..5}; do ...; done. Or for ((i=0; i<5; i++)).
    • Read lines → while read -r line; do ...; done < file. Safe with spaces in a line.
    • Split columns → while IFS=, read -r a b. IFS is the separator.
    The problem

    for x in $(cat file) cuts every line at its spaces, and a loop after a pipe loses the variable it set.

    The fix: Read lines with while IFS= read -r line; do ...; done < file, and quote "$f" in every loop.
    Type it

    for loops

    Type bash first: these snippets are bash, and zsh splits words differently. Type exit to return to zsh.

    {1..$n} does not expand a variable. Use seq. GNU seq works the same on Linux.

    Type it

    while and until

    while repeats as long as its test passes. until repeats as long as it fails.

    Type it

    Read lines and columns

    Use while read -r to take one line at a time. Feed it a file with < file.

    || [[ -n $line ]] keeps a last line that has no newline at the end: read fails on it, but $line is still set.

    Rules and review depth

    Loops at a glance

    01Pick a loop

    Pick by what you are walking.

    TaskWrite
    Loop over every filefor f in *.txt; do ...; done
    Repeat a fixed countfor i in {1..5} or for ((i=0; i<5; i++))
    Repeat a count held in a variablefor i in $(seq 1 $n)
    Read every line of a filewhile IFS= read -r line || [[ -n $line ]]; do ...; done < file
    Split a line into columnswhile IFS=, read -r a b; do ...; done < file
    02Stop, skip or repeat

    Four words steer a loop.

    TaskWrite
    Leave the loop nowbreak
    Skip to the next roundcontinue
    Repeat while a test passeswhile test; do ...; done
    Repeat until a test passesuntil test; do ...; done
    03Avoid two traps

    Both lose data without an error.

    TaskWrite
    Loop over lines that contain spaceswhile IFS= read -r x; do ...; done < file, not for x in $(cat file)
    Keep a variable set inside the loopwhile read ...; done < file, not cmd | while read
    Worked application

    Add up the ages in a CSV

    The setup

    people.csv has name,age on each line. You want the total of the ages.

    1. Keys: total=0 · Start the sum.
    2. Keys: while IFS=, read -r name age; do total=$((total + age)); done < people.csv · Each line splits at the comma. The loop reads from the file, so total survives.
    3. Keys: echo "total age: $total" · Print the sum.
    You see
    total age: 106
    Why it matters: Redirecting the file in keeps the loop in your shell, so the variable is still set afterwards.
    Your turn

    Practice: loops

    MechanismQ1

    Why is count still 0 after cat f | while read -r x; do count=$((count+1)); done?

    hint

    Where does each side of a pipe run?

    step-by-step solution
    1. Each side of a pipe runs in its own subshell.
    2. The loop changes a copy of count.
    3. The copy disappears when the pipe ends.
    Final answer: Feed the loop with < f instead of a pipe.
    KeystrokesQ2

    Which loop prints a.txt, b.txt and the rest of the .txt files, even when a name has a space?

    hint

    A glob, with quotes on the variable.

    step-by-step solution
    1. Use for f in *.txt; do.
    2. Write echo "$f".
    3. Close with done.
    Final answer: for f in *.txt; do echo "$f"; done.
    ApplicationQ3

    Print Ada, Bo and Cy from people.csv, one per line.

    hint

    Split at the comma and ignore the age.

    step-by-step solution
    1. Write while IFS=, read -r name age; do.
    2. Write echo "$name".
    3. End with done < people.csv.
    Final answer: while IFS=, read -r name age; do echo "$name"; done < people.csv.
    Common mistakeQ4

    for f in *.zip prints *.zip when there are no zip files. How do you stop that?

    hint

    Test that the file exists inside the loop.

    step-by-step solution
    1. With no match the pattern stays as text.
    2. Add [[ -e $f ]] || continue as the first line of the loop.
    Final answer: for f in *.zip; do [[ -e $f ]] || continue; ...; done.

    Script input

    Read arguments, flags and typed answers, and stop with a usage message on bad input.

    The one idea

    A script reads its arguments from $1, $2 and $@, and its flags from a case loop or getopts.

    • Read the first argument → $1. $2 is the second, $# is the count.
    • Give a default → ${1:-world}. Used when $1 is empty.
    • Parse flags → getopts "vn:" opt. A colon means the flag takes a value.
    • Ask the user → read -p "Name: " name. -s hides it, -t 5 times out.
    The problem

    Your script breaks on bash backup.sh "my folder", or runs with a missing argument and does the wrong thing.

    The fix: Quote "$@" and "$1", require what you need with ${1:?usage}, and print usage and exit 1 on bad input.
    Type it

    Arguments

    Each script is created with a here-doc and run with bash name.sh args, so it works from zsh too.

    Type it

    Defaults, required values and usage

    ${1:-x} falls back to x. ${1:?message} stops the script with the message when $1 is missing.

    usage() { ...; } is a function. Module 11 covers them.

    Type it

    Flags

    Two ways to read flags: a case loop with shift, or the built-in getopts.

    In getopts "vn:", v is a switch and n: takes a value, held in $OPTARG. OPTIND is the index of the next argument, so shift $((OPTIND - 1)) leaves only the files.

    Type it

    Ask the user

    read waits for a typed line. These scripts wait for you, so type the answer and press Enter.

    Rules and review depth

    Script input at a glance

    01Read the arguments

    Set by bash when the script starts.

    TaskWrite
    Read the first argument$1 ($2 is the second)
    Count the arguments$#
    Pass every argument on, each kept whole"$@"
    Print the script name$0
    Avoid this one$* cuts arguments at spaces
    02Default, required or checked

    Decide what a missing argument means.

    TaskWrite
    Use a default when $1 is empty${1:-world}
    Stop with a message when $1 is empty${1:?usage: x FILE}
    Run your own usage check[[ $# -eq 2 ]] || usage
    03Ask the user

    Flags that change how read waits.

    TaskWrite
    Show a promptread -p "Name: " name
    Hide what is typedread -s pw
    Give up after 5 secondsread -t 5 a
    Keep backslashes as typedread -r line
    Worked application

    Greet by name with a default and a loud switch

    The setup

    parse.sh greets world by default, takes -n NAME, and shouts with -l.

    1. Keys: bash parse.sh · No flags: the default name stays.
    2. Keys: bash parse.sh -l -n Bo · The loop reads -l, then -n and its value with shift 2.
    You see
    Hello, world
HELLO, BO
    Why it matters: A case loop with shift handles flags in any order, and the *) branch rejects anything else.

    Practice: script input

    MechanismQ1

    What do "$@" and $* do differently with one "two words" three?

    hint

    Count the words each one produces.

    step-by-step solution
    1. "$@" gives three words, keeping two words together.
    2. Unquoted $* gives four words.
    Final answer: "$@" keeps each argument whole. $* cuts at spaces.
    KeystrokesQ2

    Which line sets dir to the first argument, or . when none is given?

    hint

    A default with a colon and a dash.

    step-by-step solution
    1. Use ${1:-.}.
    2. Assign it with dir=.
    Final answer: dir=${1:-.}.
    ApplicationQ3

    Write the line that makes a script stop with usage: run.sh FILE when no file is given.

    hint

    A required value with a question mark.

    step-by-step solution
    1. Use ${1:?...}.
    2. Put the usage text after the question mark.
    Final answer: file=${1:?usage: run.sh FILE}.
    Common mistakeQ4

    Your getopts "vn:" script sees -n but $name is empty. What did you forget?

    hint

    Where does getopts put a flag's value?

    step-by-step solution
    1. A flag that ends in : takes a value.
    2. The value is in $OPTARG, not in $1.
    Final answer: Write n) name=$OPTARG ;;.
